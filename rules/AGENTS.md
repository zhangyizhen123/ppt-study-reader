# PPT 伴读提问响应规则

当用户在对话中发送以 `【PPT伴读提问】` 开头的消息时，说明这是用户通过「PPT 伴读」鼠标选中并直接发来的课件页面提问。请按以下方式解答：

1. **先看选区截图（如有）**：
   - 如果消息中包含 `选区截图ID:` 且可用 MCP 工具 `read_ppt_crop`，可调用 `read_ppt_crop({ cropId })` 查看截图；
   - 如果包含 `选区截图:` 本地 `.png` 路径且支持 `read_file`，**先调用 `read_file` 查看该截图**，再结合提取文字、课件名、页码与提示作答，这样可以准确看懂架构图、公式推导、电路/曲线图和代码截图。
2. **通俗直观、结合专业直觉**：优先用大白话类比 + 清晰步骤拆解概念，帮学生把“抽象定义 / 公式 / 图表 ↔ 具体物理意义或实际应用”串联起来，少堆砌无助于当前理解的冷门术语。
3. **结合页面重点级别把握节奏**：
   - 如果当前页标注为 `🔴 预习可跳过` / `🔴 可跳过`，先用 1~2 句话告诉用户“这页在当前复习/预习计划里属于低优先级，大概知道干嘛的就行”，然后再简明回答疑问，把精力留给主干考点。
   - 如果当前页是 `🟢 重点精读` 或 `🟡 速览了解`，讲清楚“为什么重要 + 核心结论 + 常见考试/做题坑点”。
4. **控制篇幅**：重点讲透用户选中的这一块，分点短小清晰，方便对照 PPT 快速消化后继续往后翻页。
5. **浏览器伴读的提问监听（Claude Code 等）**：如果之前在后台挂起了 `start_web_reader` 返回的 `listenCommand`，它因收到提问而退出时，先调用 `get_pending_ppt_question` 取回图文作答；答完后用同一条命令重新在后台挂起，保证下一次提问也能自动送达。
